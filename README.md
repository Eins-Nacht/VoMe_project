# Audiary

## วิธีดำเนินงาน
โครงการ Audiary ใช้แนวทางการพัฒนาระบบแบบแยกส่วน โดยแบ่งเป็น 3 ส่วน
1. ส่วนของผู้ใช้งาน (Frontend)
เป็นส่วนการผู้ใช้สมัครหรือ Log in เพื่อทำการอัดหรือส่งไฟล์เสียงไปยังส่วนของระบบการจัดการเสียง เมื่อประมวลผลเสร็จแล้ว ผู้ใช้ก็สามารถแก้ไข Summary ที่ได้มาได้
2. ส่วนของระบบจัดการข้อมูลและประมวลเสียง (Backend)
เป็นส่วนการใช้ในการจัดเก็บไฟล์เสียง ประมวลเสียงและสรุปให้เป็นการอธิบาย Summary
3. ส่วนการสื่อสารระหว่าง Frontend กับ Backend (API)
เป็นส่วนที่ทำการส่งข้อมูลหรือรายละเอียดของผู้ใช้/model ของ LLM เข้ามาทำงานร่วมกับระบบ Frontend และ Backend

3. ผู้ใข้งานที่เคยใช้งานมาแล้ว --> ลงชื่อเข้าระบบ --> ลืมรหัสผ่าน --> แก้ไขรหัสผ่าน --> ลงชื่อเข้าระบบอีกครั้ง --> อัดเสียงหรือเลือกใช้ไฟล์เสียงการประชุม --> รอการประมวลผล --> เก็บ/แก้ไข Summary --> เก็บหรือลบไฟล์เสียง --> ออกจากระบบ

### Activity Diagram
<img src=activity.png>
ลำดับการทำงานของผู้ใข้งาน
1. เริ่มต้นและสร้างกิจกรรม
จุดดำด้านบนคือจุดเริ่ม ผู้ใช้สร้าง Event แล้วเลือกวิธีนำเข้าเสียง

2. เลือกวิธีป้อนเสียง
จุดตัดสินใจ “Choose method?” แยกเป็นสองทาง:

* Record: บันทึกเสียง
* Upload: เลือกไฟล์เสียงที่มีอยู่
จากนั้นเส้นทางทั้งสองรวมกลับเข้าสู่กระบวนการเดียวกัน

3. ตรวจสอบไฟล์เสียง
ระบบตรวจสอบไฟล์และมีจุดตัดสินใจ “Valid Audio?”
* ถ้า ไม่ผ่าน ระบบแสดงข้อผิดพลาดเกี่ยวกับไฟล์เสียง
* ถ้า ผ่าน ระบบเริ่มประมวลผลเสียง
ถอดเสียง

4. ระบบใช้ Speech-to-Text 
* ถ้า ไม่สำเร็จ ผู้ใช้ได้รับข้อความแจ้งข้อผิดพลาดในการถอดเสียง
* ถ้า สำเร็จ ระบบดำเนินการสร้างสรุปด้วย LLM

5. สร้างและบันทึกสรุป
ระบบตรวจสอบ “AI Successful?”
* ถ้า ไม่สำเร็จ ผู้ใช้ได้รับข้อความแจ้งข้อผิดพลาดจากการประมวลผล AI
* ถ้า สำเร็จ ระบบบันทึก Transcript และ Summary แล้วผู้ใช้สามารถดูสรุปได้

6. ลองใหม่หรือจบการทำงาน
เส้นทางข้อผิดพลาดนำไปสู่การตัดสินใจ “Retry?”
* เลือก Yes เพื่อกลับไปเลือกเสียงและเริ่มใหม่
* เลือก No เพื่อจบกระบวนการ
วงกลมซ้อนด้านล่างคือจุดสิ้นสุดของกิจกรรม

## เทคโนโลยี Programming Language และ Framework
เทคโนโลยี: Faster-whisper (Speech-to-Text), Ollama Gemma 3 (LLM), Docker, SQLite3 (Database)

Programming Language: Dart (Frontend), Python (Backend + API)

Framework: Flutter, FastAPI
